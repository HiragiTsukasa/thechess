# ルールが本当に効いているかを叩いて確かめる

```bash
bash probe.sh
```

Firestore のコンソールでは**下書きと公開済みを見分けられない**。
「公開」を押し忘れても画面上は同じに見えるので、**HTTPの番号で確かめるしかない**。

匿名ユーザーを2人作って、ホスト役とよその人役で10通り叩く。

| | 叩くこと | 正しい番号 |
|---|---|---|
| 1 | 無い部屋を1件読む | **404** |
| 2 | 一覧を取る | **403** |
| 3 | 自分がホストの部屋を作る | **200** |
| 4 | 同じ番号をもう一度作る | **400**（既にある） |
| 5 | 他人がホストの欄に書く | **403** |
| 6 | 他人がゲストとして入る | **200** |
| 7 | ゲストが自分の手を書く | **200** |
| 8 | ホストが自分の手を書く | **200** |
| 9 | 他人が新しい部屋を消す | **403** |
| 10 | ホストが自分の部屋を消す | **200** |

## 読み方

**全部 403** … ルールが既定（`allow read, write: if false`）のまま。貼って「公開」を押す。

**1 が 403**（404 でなく）… 読み取りのルールに `request.resource` を使う条件が混ざっている。
読むときに `request.resource` は存在しないので、必ず 403 になる。
**404（無い）と403（読めない）を混ぜてはいけない。** キー違いとルール違反が同じ見た目になる。

**3 が 403** … `create` の条件と、送っている欄が噛み合っていない。

**5 が 200** … 他人に手を書き換えられる。`affectedKeys().hasOnly([...])` の綴りを確認。
