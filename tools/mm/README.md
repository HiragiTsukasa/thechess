# マッチングの取り合いを確かめる

```bash
node sim.js
```

実機2台でしか踏めない競合を、同じ手順で回して数える。
1ティックがクライアントのループ1周で、順序は毎回混ぜる。

```
手順1  自分のドキュメントを読む（掴まれていれば host として確定）
手順2  待っている人を読む
手順3  掴む
```

手順1で読んだ自分のバージョンを手順3の条件に使うので、
**実物と同じ往復のずれ**が入る。ここがずれていると意味のある数字が出ない。

## 測った結果

| 人数 | 何もなし | 向き固定だけ | 向き固定＋原子化 |
|---|---|---|---|
| 4人 | 取り残し164 | 取り残し84 | **0** |
| 8人 | 取り残し503 | 取り残し354 | **0** |
| 20人 | 取り残し1507 | 取り残し1178 | **0** |
| 50人 | 取り残し3866 | 取り残し3008 | **0** |

（各300回、延べ人数ぶん）

## 2つの対策

**向き固定** … 掴むのは UID が自分より大きい相手だけ。
どの二人の間でも掴む向きが一方向に決まる。

**原子化** … 「相手を matched にする」と「自分を列から外す」を
1回の `:commit` で行い、**両方の updateTime** を条件に付ける。

効くのは原子化の方。向き固定だけだと、A が B を掴んだ直後に B が C を掴み、
**A だけが宙に浮く**（B はもう C と繋ぐ気でいる）。自分の updateTime も条件に
入れておけば、掴まれた側の掴みは必ず失敗し、次の周回で自分が掴まれたことに気付く。

なお「両者が同じ役になって誰も待ち受けない」は起きない。
ループの先頭で自分が掴まれていないか見ているため。
